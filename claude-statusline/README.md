# Claude Code Status Line

Кастомный статус-бар для Claude Code — модель, контекст, лимиты и расходы в реальном времени.

> Обновлено 2026-08-19 09:09

```
Opus 5 | К:  ◼◼◻◻◻◻◻◻◻◻ 26% (266k|1M) $0.21 | С: 266k $11.15
.      | 5ч: ◼◼◼◼◻◻◻◻◻◻ 40% 1:56 | Н: ● 88% 5ч13м
.      | Д: 6M $360 | 7д: 191M $4607 | 30д: 280M $6878
```

## Быстрая установка

Отдай ссылку на этот репо своему Claude Code и скажи: **«Установи этот status line»**

Клод сам склонирует репо, поставит зависимости, скопирует скрипт, обновит настройки и проверит — всё автоматически (инструкция для него — в [CLAUDE.md](./CLAUDE.md)).

## Ручная установка

```bash
# 1. Зависимости
brew install jq            # обязательно
npm install -g ccusage     # опционально — строка 3 (расходы). ВАЖНО: версия >= 20

# 2. Скопировать скрипт
cp statusline.sh ~/.claude/statusline.sh
chmod +x ~/.claude/statusline.sh
mkdir -p ~/.claude/cache/statusline

# 3. Добавить в ~/.claude/settings.json (вмержить в существующий файл, не затирать!)
# "statusLine": { "type": "command", "command": "bash ~/.claude/statusline.sh" }

# 4. Перезапустить Claude Code
```

`bc` и `jq` должны быть в PATH. На macOS `bc` уже есть, в минимальных Linux-образах — поставить.

## Что означает каждый элемент

### Строка 1 — Модель + Контекст + Сессия

| Элемент | Пример | Значение |
|---------|--------|----------|
| `Opus 5` | | Текущая модель |
| `К:` | `◼◼◻◻◻◻◻◻◻◻` | Загрузка контекстного окна (`◼` занято, `◻` свободно) |
| `26%` | | Процент использования контекста |
| `(266k\|1M)` | | (использовано токенов \| размер окна) |
| `$0.21` | | Стоимость последнего запроса |
| `С:` | `266k $11.15` | Итоги сессии: токены + стоимость |

Процент считается от *эффективного* окна — размер минус 10k буфера под ответ.

### Строка 2 — Rate Limits (лимиты подписки)

| Элемент | Пример | Значение |
|---------|--------|----------|
| `5ч:` | `◼◼◼◼◻◻◻◻◻◻ 40%` | 5-часовой лимит: шкала + % |
| `1:56` | | Время до сброса (часы:минуты) |
| `Н:` | `● 88%` | Недельный (7-дневный) лимит: иконка + % |
| `5ч13м` | | Время до сброса (`Nд Mч` или `Mч NNм`) |

Иконки-пирожки: `○` ≤20% · `◔` ≤40% · `◑` ≤60% · `◕` ≤80% · `●` >80%

> **Никакого API и токена.** Claude Code сам кладёт лимиты в stdin-пейлоад статусбара —
> `.rate_limits.{five_hour,seven_day}.{used_percentage, resets_at}`. Кэша у этой строки
> нет и не должно быть: данные всегда свежие.
>
> Ранняя версия скрипта дёргала `https://api.anthropic.com/api/oauth/usage` суточным
> claude.ai-токеном из Keychain. Токен протухал — строка замерзала на старом кэше и
> показывала `-`. **Не возвращать этот путь.** Требуется свежий Claude Code (поле
> `.rate_limits` в stdin) и подписка Claude Pro/Max.

### Строка 3 — Расходы

| Элемент | Пример | Значение |
|---------|--------|----------|
| `Д:` | `6M $360` | Токены + стоимость за сегодня |
| `7д:` | `191M $4607` | За последние 7 дней |
| `30д:` | `280M $6878` | За последние 30 дней |

> Источник — `ccusage daily --json --offline`, кэш 15 минут, обновление в фоне.
> Токены = input + output + cacheCreation (cacheRead не считаем).

## ⚠️ ccusage: обязательно версия ≥ 20 и флаг `--offline`

Если строка 3 показывает `$0` при явно ненулевом расходе — почти всегда дело в ccusage:

- ccusage тянет прайсинг с `raw.githubusercontent.com/BerriAI/litellm/...`. На части каналов
  этот файл недоступен наглухо: ~90 секунд и 0 байт. Без прайсинга `--mode calculate`
  считает всё по нулям.
- На 18.x это не лечится: офлайн-снимок цен там старый (нет Opus 5 / Sonnet 5 / Fable 5),
  а override через `LITELLM_PRICING_URL` не срабатывает даже на рабочее зеркало.
- `--mode auto` / `--mode display` тоже не спасают: Claude Code не пишет `costUSD` в
  транскрипты, брать оттуда нечего.

На 20.x всё решается флагом **`--offline`**: снимок цен свежий, сеть не нужна вовсе,
прогон ускорился с >2 минут до ~5–10 секунд.

Ещё одно отличие 20.x: **ключ дня в JSON называется `period`, а не `date`**. Скрипт
фильтрует как `(.period // .date // "")` — иначе окно за 7 дней молча не матчится и `7д`
показывает `$0` при живом `30д`.

## Защита от thundering herd

`statusline.sh` выполняется на **каждую отрисовку в каждой сессии**. Если параллельно
открыто N сессий и кэш протух, без защиты каждая форкнет свой `ccusage` — на 14+ сессиях
это load average 40+ и фактическое зависание машины.

Решение — atomic-лок на `mkdir` (`_bg_locked`): тяжёлую задачу в каждый момент времени
запускает ровно одна сессия, остальные читают кэш.

**Инварианты — нарушение любого валит машину:**

1. **Порог протухания лока (1800 с) обязан превышать длительность самой долгой задачи.**
   Раньше стояло 120 с — с тех времён, когда ccusage укладывался в ~30 с. Транскрипты
   выросли, прогон перевалил за 2 минуты, и каждый прогон стал переживать собственный лок:
   следующая отрисовка считала лок протухшим и запускала вторую копию, та третью. Итог —
   стопка ccusage по 100% CPU, load average ~20 на 16 ядрах и лаги ввода.
2. **TTL кэша (900 с) тоже должен превышать длительность прогона**, иначе кэш протухает
   раньше, чем заполняется, и ccusage крутится непрерывно.
3. **Фоновый QoS** — `taskpolicy -b nice -n 19` (фолбэк `nice -n 19`): задача уходит на
   энергоэффективные ядра и уступает интерактиву.
4. **`.tmp` промотировать только после проверки содержимого** (`jq -e '.daily | length > 0'`).
   Убитый на середине ccusage выходит с кодом 0 — проверка только по коду возврата затрёт
   хороший кэш пустышкой, и 15-минутный TTL закрепит её надолго. Кэш читать через `[[ -s ]]`,
   не `[[ -f ]]`.

Проверить, что ничего не размножилось: `ps ax | grep -c '[c]cusage'` — должно быть 0 или 1.

## Диагностика

| Симптом | Причина | Фикс |
|---|---|---|
| Строка 2: `5ч: — \| Н: —` | Claude Code не прислал `.rate_limits` (старая версия или нет подписки) | обновить Claude Code |
| Строка 2 показывает `-` вместо времени | пробуют тянуть лимиты из API/токена | читать stdin `.rate_limits` |
| Время сброса отрицательное | `resets_at` — unix epoch, а не дельта | считать `resets_at - now` |
| Суммы в строке 3 схлопнулись в `$0` | ccusage не получил прайсинг | ccusage ≥ 20 и флаг `--offline` |
| `7д` нулевое при живом `30д` | в ccusage 20 ключ дня `period`, а не `date` | фильтр `(.period // .date // "")` |
| Строка 3 пустая при первом запуске | кэш холодный, ccusage считает в фоне | подождать минуту |
| Машина в полке, ввод лагает | ccusage размножился — лок протухает раньше, чем заканчивается прогон | см. инварианты выше |

## Тест без Claude Code

Скормить скрипту пробный payload (`resets_at` — эпоха, считаем от `now`, чтобы вывод был
реалистичным):

```bash
now=$(date +%s)
echo "{\"model\":{\"display_name\":\"Opus 5\"},
       \"context_window\":{\"context_window_size\":1000000,
         \"current_usage\":{\"input_tokens\":266000}},
       \"rate_limits\":{\"five_hour\":{\"used_percentage\":18,\"resets_at\":$((now+10800))},
                        \"seven_day\":{\"used_percentage\":34,\"resets_at\":$((now+216000))}}}" \
  | bash ~/.claude/statusline.sh
# → Opus 5 | К:  ◼◼◻◻◻◻◻◻◻◻ 26% (266k|1M) ... | 5ч: 18% 3:00 | Н: ◔ 34% 2д12ч
```

## Кастомизация

| Что | Как |
|-----|-----|
| Убрать расходы (строка 3) | Удалить блок `# LINE 3: EXPENSES` из `statusline.sh` |
| Убрать лимиты (строка 2) | Удалить блок `# LINE 2: RATE LIMITS` |
| Изменить ширину шкалы | Последний аргумент в вызовах `bar()` (по умолчанию 10) |
| Изменить символы шкалы | Заменить fill/empty, напр. `'■' '□'` вместо `'◼' '◻'` |
| Добавить своё поле | Ярлыки на строках 2-3 добиваются пробелами до ширины самого длинного (`5ч:`) — иначе строка «съезжает» |
| Удалить | Убрать `"statusLine"` из `~/.claude/settings.json`, удалить `~/.claude/statusline.sh` |

Доступные поля stdin: `.model.{id,display_name}`, `.context_window.*`, `.cost.*`,
`.rate_limits.{five_hour,seven_day}.{used_percentage,resets_at}`, `.session_id`, `.cwd`,
`.workspace.*`, `.effort.level`, `.thinking.enabled`, `.transcript_path`, `.version`.

## Платформа

- **macOS** — работает из коробки.
- **Linux** — все три строки работают после двух правок в `~/.claude/statusline.sh`:
  1. `stat -f %m` → `stat -c %Y` (везде)
  2. `date -v-30d +%Y%m%d` → `date -d '30 days ago' +%Y%m%d`, `date -v-7d +%Y-%m-%d` → `date -d '7 days ago' +%Y-%m-%d`

  Keychain больше не нужен нигде: лимиты приходят из stdin. `taskpolicy` на Linux
  отсутствует — скрипт сам откатится на `nice -n 19`.

## Что изменилось с прошлой версии

- **Строка 2 больше не ходит в API.** Лимиты берутся из stdin `.rate_limits` — ни токена,
  ни Keychain, ни кэша. Работает на годовом OAuth-токене нативно.
- **Шкала контекста** — те же символы `◼◻`, что и у лимитов (было `◆◇`).
- **ccusage ≥ 20 + `--offline`** — иначе расходы схлопываются в `$0`.
- **Ключ дня `period`** (в ccusage 20 переименован из `date`).
- **Порог протухания лока 120 с → 1800 с**, TTL кэша расходов 60 с → 900 с.
- **ccusage запускается в фоновом QoS** (`taskpolicy -b nice -n 19`).
- **Кэш промотируется только после проверки содержимого** — убитый прогон больше не
  затирает хорошие данные пустышкой.
